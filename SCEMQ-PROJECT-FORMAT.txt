AUTHORING MODEL
Project-level: Scene Manager, Characters, Inventory, Game UI, Variables, Settings.
Scene-level: Visual Config, Logic, Dialogues.

Characters are defined once at project level, then placed into scenes by ID. Dialogue speakers and startDialogue actions only reference project character IDs.

Start Dialogue actions can optionally select a starting node from that character's dialogue in the current scene. Blank node means the entry node.

PORTABLE SCENE IMPORT
SCEMQ v0.4 adds a single-file scene package format (*.scemq-scene.json). A package can define missing characters, inventory items, global variables, the full scene, and optional embedded assets. See SCEMQ-SCENE-PACKAGE-FORMAT.txt.

BACKWARD COMPATIBILITY
Older SCEMQ project/scene data is upgraded to v0.4 defaults when loaded. Existing v0.3 authoring files remain compatible.

CAMERA VIEW SCALE (v0.5.4)
Each gameplay scene may set scene.visual.<sceneId>.json -> viewport.zoom.
The project Game UI still owns the fixed on-screen viewport rectangle. Camera zoom is one scalar, so the world view always inherits that viewport's aspect ratio.
- 1.00 = 100% / one world pixel per viewport pixel
- 0.75 = zoomed out / more world visible
- 1.25 = zoomed in / less world visible
Existing scenes without viewport.zoom load as 1.00.


SCENE MANAGER (v0.5.5)
project/project.scene-manager.json stores:
- sceneOrder: stable authored ordering of scene IDs
- connections: directional structural links between scenes
- notes: optional director/project flow notes

Connections may be marked bidirectional and classified as progression, return, hub, newGame or custom. In v0.5.5 these links document/organize project flow; runtime gating remains in scene Logic and Exit conditions so puzzle conditions have one authoritative home.


SCALE AREAS (v0.6)
scene.visual.<sceneId>.json -> scaleAreas[]
Each area is a polygon with topScale and bottomScale. A character whose feet
anchor is inside the polygon renders at topScale on the polygon's top edge and
bottomScale on its bottom edge, interpolated linearly on Y. The feet point stays
pinned while the sprite scales. Scenes without scaleAreas render at 1.00.

STRING TABLE (v0.6)
project/project.strings.json stores:
- defaultLanguage and the list of target languages
- entries keyed by authored location, each with source text, context and a
  translation per language
Keys are derived from where a string lives (scene, rule, dialogue node, object),
so they are recomputed at runtime and never written back into scene files. A
missing translation falls back to the source string. settings.language selects
the runtime language.

SAVES (v0.6)
Save records are versioned (SAVE_FORMAT) and carry the scene id and name, the
full runtime state, player position, camera, active character and playtime.
Records written by earlier versions are migrated on load.
