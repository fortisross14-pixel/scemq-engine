SCEMQ PROJECT FORMAT v0.2

SCEMQ projects are ordinary folders. Scene content stays scene-scoped; reusable project content lives in project-level modules.

PROJECT ROOT
scemq.project.json

project/
  project.ui.json
  project.variables.json
  project.settings.json

characters/
  <character-id>.character.json

inventory/
  <item-id>.item.json

assets/
  ui/
  characters/
  inventory/

scenes/
  scene1/
    scene.meta.scene1.json
    scene.visual.scene1.json
    scene.logic.scene1.json
    objects/
      <object-id>.object.scene1.json
    dialogues/
      <character-id>.dialogue.scene1.json
    assets/
      <background, object, state, music and ambient files>

SCENE-SCOPED NAMING
Scene IDs remain present in every authored scene filename. For example:
pindle.dialogue.scene1.json
pindle.dialogue.scene7.json
fire-alarm.object.scene1.json
scene.logic.scene1.json
scene.visual.scene1.json

PROJECT UI
project/project.ui.json stores:
- total game screen dimensions
- the fixed viewport rectangle through which the scene is shown
- persistent UI elements
- verb-button actions
- inventory layout
- status text
- optional cursor image paths

CHARACTERS
characters/<id>.character.json stores reusable character identity and runtime defaults:
- name
- playable capability
- walking speed
- default facing
- portrait/idle/walk asset slots

A scene object tagged character references a character ID and can be NPC or playable in that scene.
Dialogue still remains scene-scoped.

INVENTORY
inventory/<id>.item.json stores reusable item definition and visual asset.
Runtime ownership is game state, not authoring data.

VISUAL CONFIG
scene.visual.<scene>.json stores scene-wide layout/runtime geometry:
- canvas
- dedicated background
- player assignment/start
- spawn points
- walk polygons
- depth polygons
- camera settings
- ordered object references

Each object remains in its own *.object.<scene>.json file.
Objects can define multiple named visual states while retaining one transform/hotspot.

LOGIC
scene.logic.<scene>.json stores scene variables and rules.
Rules contain an event, optional conditions and ordered actions.
Global variables live in project/project.variables.json.

DIALOGUE
Each talkable scene character uses:
<character-id>.dialogue.<scene>.json

IMPORT / AI COLLABORATION
SCEMQ can import/export modular content without requiring code edits:
- scene visual packages and individual object files
- scene logic files
- scene dialogue files
- project character files
- project inventory item files
- project UI
- project variables
- project settings

ASSETS
Scene assets are copied into that scene's assets directory.
Reusable character/inventory/UI assets are copied into project assets directories.
The JSON owns paths; the editor/runtime loads those files directly from the selected local project folder.

BACKWARD COMPATIBILITY
SCEMQ v0.2 loads v0.1 scene visual/object files and supplies v0.2 defaults for camera, player, spawn, anchors, visual states, interaction points and runtime geometry. Saving writes the updated v0.2 schema.
