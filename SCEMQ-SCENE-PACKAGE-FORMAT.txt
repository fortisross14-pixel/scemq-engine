SCEMQ SCENE PACKAGE FORMAT v1
Engine: SCEMQ v0.4+

PURPOSE
A complete first pass of a scene can be exchanged as one portable JSON file:

  scene1.scemq-scene.json

The user does not need to create characters, inventory items, or global variables first if the package contains their definitions.

TOP-LEVEL CONTRACT
{
  "schemaVersion": "0.4",
  "kind": "scemq-scene-package",
  "packageVersion": 1,
  "sceneId": "scene1",
  "name": "Department Office",
  "dependencies": {
    "characters": [...full SCEMQ character definitions...],
    "inventory": [...full SCEMQ inventory item definitions...],
    "variables": [...global variable definitions...]
  },
  "softDependencies": {
    "scenes": [{"id":"scene2","resolvedAtExport":false}]
  },
  "scene": {
    "meta": {...},
    "visual": {...},
    "logic": {...},
    "objects": [...],
    "dialogues": [...]
  },
  "assets": []
}

DEPENDENCY RULES
Characters and inventory are hard references. A missing ID must either already exist in the receiving project or be defined in dependencies.

Global variables referenced by the scene must likewise exist or be defined. Scene-local variables belong to scene.logic and are not project dependencies.

Destination scenes are soft references. An exit may point to a scene that has not been created yet. SCEMQ keeps that ID unresolved until the destination scene is later created/imported.

CONFLICT RULES
IDs are authoritative.
- Existing character ID: reuse existing project character.
- Existing inventory item ID: reuse existing project item.
- Existing global variable ID: reuse existing variable.
- Existing scene ID: importer offers Replace Existing or Import As New Scene.

Import As New rewrites the sceneId across the package. Self-referencing exits/changeScene actions are remapped to the new ID; references to other scenes are preserved.

ASSETS
Assets are optional. A package generated by ChatGPT may use empty asset paths so SCEMQ renders editable placeholders.

SCEMQ's Export Scene Package command embeds currently referenced scene, character, and inventory assets into the JSON as base64 records. On import, SCEMQ restores those files to the correct project folders.

VALIDATION BEFORE IMPORT
SCEMQ checks:
- package kind/version
- core scene modules exist
- required character/item/global-variable definitions
- visual object references
- playable character object reference
- rule object targets
- Start Dialogue character + starting-node references
- Set Visual State target + state name

The preview reports what will be created, what will reuse existing project IDs, and which destination scenes remain unresolved.

START DIALOGUE AT NODE
The startDialogue action uses:
  targetId = project character ID
  value    = optional dialogue node ID

Blank value starts at the dialogue's entry node.
